# Per-call inference submission limits

The Sparra manifest enables these limits in the existing per-call service
instances. Generic voice consumers retain their previous behavior.

STT reserves at most 600 seconds of submitted PCM, including native padding,
overlap and closing segments. It accepts the complete PCM16 WAV generated by
Pipecat 1.12, rejecting additional chunks or trailing bytes before dispatch.
The OpenAI transcription client has automatic retries disabled for Sparra.

TTS reserves at most 20,000 Unicode characters from the final request input.
Ordinary speech has 19,975 characters available; 25 are reserved for the fixed
farewell. Only the application-owned farewell frame's native context can use
that reserve. Identical model-generated text has no such authority.

Reservations happen before HTTP dispatch, without an intervening await.
Cancellation, timeout, context changes and cleanup do not refund or reset them.
Each call has independent counters. Exhaustion uses the existing fatal error
path; a spoken farewell after quota exhaustion is not guaranteed.

These are local submission limits, not a maximum provider invoice. This lot
does not qualify native billed LLM input/output tokens, remote fallback attempts,
carrier hangup timing, or unattended number availability. The existing session
timeout, terminal cleanup and provider qualification remain separate controls.

Sparra's LLM reserves the completion ceiling from each final SDK-prepared JSON
request: up to 13,952 ordinary tokens, each request at most 256, plus 2,048 for
one actual retained-call result after cleanup. It accepts exactly one positive
integer token ceiling and at most one completion. SDK retries and HTTP redirects
are disabled; reservations are never refunded. A schema-bearing ordinary request
cannot claim the final allowance. Local refusal closes ordinary inference through
Pipecat's existing fatal error path; the same client remains available for that
single final result attempt before its owner closes it.

The 16,000 total bounds requested ceilings, not provider token accounting. The
250,000 native input-token allowance remains unqualified until the selected
provider's exact prompt, schema and tokenizer transformations are established.

`budget_observation.collect_budget_observation` is an inert account metadata
reader. Its frozen identity binds the original credential SHA-256 fingerprints,
OpenRouter creator-account and Telnyx charges user-account SHA-256 fingerprints,
active DID/connection, original UTC midnight accounting start and exact key expiry.
The caller supplies `SecretStr` credentials, UTC/monotonic clocks and owns the
HTTPX client, whose transport and hooks must neither retry nor log secrets/bodies.
It performs only fixed-origin GETs, disables redirects, limits each decoded body
to 2 MiB and the whole acquisition to 15 seconds. Refusals have constant errors;
cancellation propagates. No provider response body or secret is retained in facts.

Facts include acquisition start/end UTC, exact Decimal spending/cash, the USD5
OpenRouter key limit, remaining limit, no-reset state and expected expiry, complete
active call-control IDs and a digest of the ordered request/body provenance.
OpenRouter cash is account credits minus account usage, read separately from key
headroom using the same bound inference credential. Missing/forbidden credits
refuse observation; a management-key flag is not a capability test. Native-host
capability remains a deployment qualification requirement.

Telnyx spending preserves the seven original usage products (negative usage never
refunds spend) plus absolute charges, with a separate USD wallet read. Both the
original top-level charges response and the documented SDK `data` envelope have
the same validated monetary/account contract. Date windows remain anchored to
the original start and split at 31 days, the provider's maximum report interval.
Usage uses the original flat `page_size`; numbers use native `page[size]`; active
calls use `total_items`, `cursors.after/before` and top-level `next/previous` metadata.
Only complete results of at most 100 rows per response are accepted; multipage or
continuation results fail closed. Collection age starts at acquisition start,
never the final request. The admission consumer must enforce its 60-second age,
persist reported floors and apply its policy: these facts issue no grant, enroll
no authority and write no ledger or file. Call-control IDs are sensitive and are
excluded from the observation's repr; consumers must also keep them out of logs.

## Continuous original-pilot authority

Strict Sparra requires `VOICE_OWNED_BUDGET_POLICY_PATH` and
`VOICE_OWNED_BUDGET_POLICY_SHA256`. The latter is the canonical policy digest
(`OwnedPilotBudgetPolicy.sha256`), not a digest of JSON whitespace. The protected
policy binds original account/credential fingerprints, DID/connection, original
accounting start and historical spending anchors, paid/key expiry, the qualified
profile and exact runtime/image/bundle/inference consumer. Its cost scope is
`original-dedicated-account-key`; account cash and original-key usage are only
normalized under that explicitly qualified dedicated scope.

The permanent SQLite slot is `sparra-original-pilot`. The operator retires the
predecessor, establishes its historical exposure and genuine paid/renewal
disposition, then runs once using the qualified strict runtime environment:

```
python -m projetv0_voice.owned_pilot_budget_cli enroll --predecessor-retired
```

This command reads authenticated metadata and refuses active/unsettled authority.
It neither buys credit nor changes provider resources. Startup never enrolls or
repairs authority. Same-policy enrollment cannot reset consumption; a different
UUID/hash/anchor/consumer cannot replace the original slot through enrollment.
Before starting from
a known restored store, the operator must suspend it explicitly:

```
python -m projetv0_voice.owned_pilot_budget_cli suspend-restored
```

An operator timeout reports `owned_budget_transition_unknown`, because the row
may commit after the timeout. The command drains and joins its writer even when
degraded, retaining late committed state. If bounded drain and cancellation
cannot close the owner, the standalone command exits with that unknown outcome;
it never returns while leaving a writer alive. Inspect the same durable authority
before deciding how to continue.

There is no automatic unsuspend/regrant path and no claim of arbitrary full-store
rollback detection. Missing authority refuses paid work. Additive legacy10 and
native-audio11 migrations preserve historical qualification rows and old logical
contents; the new table and nullable lease permit do not reinterpret those rows.

### One explicit sixth-call transition

The default original policy retains its lifetime limit of five admissions. An
explicit extended policy with `total_calls=6` can authorize exactly ordinal6
under the same separate USD5 provider caps. It cannot enroll an empty store,
reset the count, increase either monetary cap, or authorize ordinal7. There is
no periodic renewal, new budget identity, or automatic startup transition.

After retiring the predecessor and qualifying the exact new image/profile,
configure the strict operator environment with that extended policy and its
new canonical policy SHA-256, then use the **original policy's** exact hash:

```
python -m projetv0_voice.owned_pilot_budget_cli extend-sixth-call --predecessor-retired --expected-policy-sha256 ORIGINAL_POLICY_SHA256
```

The writer requires the original permanent slot at exactly `used_calls=5`,
the matching predecessor hash and policy JSON, no suspension, no active local
lease or carrier call, and no unsettled paid dispatch. The original financial
UUID, account/credential identity, accounting start, anchors, paid/key expiry,
bundle and inference profile must match. Only the finite limit and qualified
profile/runtime/image/deployment binding may change; any changed artifact must
have its truthful newly qualified digest. Fresh matching observations must pass
the original monetary, cash, remaining-key and full start-envelope checks.

The same transaction preserves all historical rows and count5, advances each
reported floor only to `max(H,S)`, replaces the exact policy binding, and rebuilds
only the budget table with a maximum count6. Legacy10 advances to12 and native
audio11 advances to13; historical schemas10/11 keep their original meaning.
Refusal leaves the schema and authority unchanged. Startup recognizes the exact
new schemas without extending authority; older images refuse those versions,
so keep the predecessor retired. A fresh observation is required before runtime
readiness. Duplicate transitions refuse and never grant another admission.
If the outcome is unknown, inspect that same durable store: the whole migration
and transition either committed together or rolled back. Never delete/reset a
ledger or retry with a new identity to resolve uncertainty.

The reserve formula and constants below remain unchanged. At count5, retained
reserves are OR1.255068/Telnyx0.62; actual affordability still requires fresh
provider observations. A committed sixth permit remains subject to its own
ordinal-minus-one checks after admission closes. This source capability does
not establish a deployed transition, a successful real call, or final invoices.

The owner authorized the remaining-reserve amendment on 21 October after
disclosure of reduced protection against delayed charges. For each provider,
use `E=max(H,S,A+m*d)` and `R(m)=R0-m*d`, where `S` is the raw authenticated report
and `H` is its durable reported high-water floor. New admission uses committed
count `m=n<total_calls` (default5, explicitly extended6); a current permit of
ordinal `k` uses `m=k-1`. It requires
`E+R(m)<=5` and `cash-(E-S)>=R(m)`; OpenRouter separately requires
`key_remaining-(E-S)>=R(m)`. Preserve `R0=6*d+uncertainty`, with original R0
OR3.780408/Telnyx1.22 and forecasts OR0.505068/Telnyx0.12. Uncertainty remains
included exactly once; minimum admitted-index reserves at m=4 are
OR1.760136/Telnyx0.74. These are separate USD5 control caps and a lifetime ceiling
of five admissions by default, or six after the single explicit transition,
not guaranteed affordable calls. The last permit may
finish after new admission closes, subject to its own checks. A larger global
count can loosen money checks, so it cannot replace a permit's ordinal minus one.
This new policy lowers retained headroom even when reported spending dominates;
it supersedes the deliberately conservative whole-reserve rule. It does not
establish final billing or an invoice ceiling. Reported high-water marks remain
separate from the pessimistic forecast, updating only as `H'=max(H,S)`. A downward provider
restatement can remain funded, but cannot lower that floor or refund an admission.
Raw spend below the original policy anchor still refuses. Each frozen committed
or pending writer view carries its own raw fact and floors. These are operational
forecasts, not invoice guarantees.

The existing writer commits receipt, pending lease, permit and increment together.
Answered-first webhooks remain inert placeholders until initiated supplies native
routing, then reuse the same permit for streaming without an extra Answer. Native
Answer/stream owners, WSS claims and session construction recheck after awaits.
A durable paid-dispatch intent survives cancellation, lease expiry and restart;
only native accepted hangup or matching verified terminal evidence settles it.
Observation refresh never clears that uncertainty.

Synchronous paid predicates read the writer's committed snapshot, not a delayed
refresh response. While COMMIT is in flight, prepared state may only restrict an
existing committed permission; it cannot grant one. Publication follows commit,
so an older observation result cannot reopen a newer busy/exhausted admission.
This readiness closure still leaves an affordable current permit usable.

The existing supervisor refreshes bounded metadata without enrolling. Budget
closure affects readiness, while `/health/live` and owned local finalization stay
available. Deployment must use liveness for process restart decisions. New starts
must fit the call/setup/finalization envelope before the absolute paid fence;
the original300s deadline is never restarted by WSS. STT/LLM/TTS dispatch and the
paid final summary also respect the fence. Existing submission limits and native
Pipecat transport/serializer remain unchanged. Closing admissions does not cancel
number rental or authorize renewal.
